# Kimi directed-L research workflow

Use this skill together with the governing repository skills
`lgrid-research`, `lgrid-invent`, and `lgrid-verify`. It coordinates work; it
does not replace their mathematical or evidence rules.

## 1. Refresh the frontier

- Authenticate to GitHub and list branches and all open PRs.
- Identify the newest commit and exact claim in each active lane.
- Read changed proof/report files, not only their titles. `main` is a literature
  snapshot, not the frontier.
- Record base commit, branch, read coverage, and unchecked dependencies.
- Keep R_3 and R_4 ledgers separate. Never promote S21/G9 conditionals.

## 2. Claim a distinct lane

Current occupied families as of 2026-11-15:

- Codex: binary-source finite capacities, hereditary rank transfer,
  collisions, short-request demands, and exact window consumers.
- Claude: ternary-source grid compatibility, joint fiber deficits/MS*, prefix
  certificates, and local triangle refutations.

Prefer an untouched representation or scale interaction. Examples are
starting questions, not assigned truths: quotient-color constraints on many
subsquares; off-diagonal words coupled to the main diagonal; or explicit
multiscale full-square recursion. Check the newest branches again before each
new round.

Write `CONTRACT.md` before the experiment:

```text
Object and coordinates:
Exact proposition and quantifiers:
Information retained that the incumbent loses:
Cheapest discriminating test and stop condition:
Consumer chain if successful:
Nearest known obstruction:
Status and evidence required:
```

## 3. Time-box and pivot

Run the smallest exact test capable of changing the route. On a counterexample,
record the full witness and nearest surviving variant. On a weak consumer,
record the quantitative gap and stop. On UNKNOWN/timeout, record UNDECIDED and
do not enlarge the same search automatically. Keep an alternative that does
not depend on the failed premise.

## 4. Produce reusable evidence

Use a new dated directory under `research/` with the contract, theorem or
counterexample, standalone checker, raw result, and report. Include commands,
actual coverage, interpreter version, hashes for important inputs, and explicit
non-claims. Distinguish mechanism, technical integration, and numerical bound.

For a new Ramsey upper bound, restart from an arbitrary coloring of the full
square and close every reduction. Otherwise state "No new Ramsey bound" at the
top. Internal review is not external peer review or Lean formalization.

## 5. Collaborate without collision

Create a separate branch from the newest appropriate checkpoint. Never rewrite
shared status files or another agent's package. Export a short handoff table:
exact statement, domain, evidence, consumer, missing bridge, and suggested
owner. Push only after local checks and English-only validation. Do not merge,
close, or rewrite PRs without separate owner confirmation.
